# 002 — the build entry, and why `build.js` is the only writer

Session: 2026-08-02

## Goal

Turn `content/*.md` plus `site.config.json` into `build/*.html` with a single entry point, so that publishing is one command and nothing under `build/` is ever authored by hand.

## What was done

- `build.js` reads `site.config.json`, walks `content/`, and renders each page through one shared layout.
- Rendered values (site title, nav, footer) come from the config rather than being repeated per page.
- `build/` was added to the documented artifact list as **output**, safe to delete and rebuild.

## Options considered

| Option | Outcome |
| :--- | :--- |
| One config file feeding every page | **Chosen** — one place to change a rendered value |
| Hard-coded title and nav in each layout | Rejected: the same value would live in N places and drift |
| A per-page front-matter override for everything | Rejected for now: more expressive, but nothing needed it yet |

## Decision

`build.js` is the only writer of `build/`, and `site.config.json` is the only place a rendered value is declared.
